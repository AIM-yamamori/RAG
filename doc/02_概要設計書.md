## 1. システム概要

就業規則(Markdownファイル)を知識源として、ユーザーの質問に対しLLMが根拠付きで回答するRAGチャットボット。Google Cloud上に構築し、Webブラウザから**Streamlitのチャット画面**を通じて利用する。フロントエンドからバックエンドまで**Pythonのみ**で実装する。

処理は大きく「データ取り込み(オフライン処理・初回のみ実行)」と「質問応答(オンライン処理)」の2つに分かれる。

## 3. 処理フローの概要

### 3.1 オフライン処理(データ取り込み)

開発者がローカル環境から1回だけ実行するバッチ処理。**Embedding APIのクォータを消費するため再実行は最小限にする。**

```
① GCS(fictworks-rule-data-501004/company_rule/)から全mdファイルを読み込む
② 00_概要_目次.md はスキップする
③ 正規表現(^##\s+(第\d+条))で条文単位にチャンク分割する(全10ファイル・82チャンク)
④ 各チャンクをGemini Embedding API(gemini-embedding-001, 768次元)でベクトル化する
   ※ output_dimensionality=768 を明示指定する(未指定時は3072次元が返るため必須)
⑤ rule_chunksテーブルをTRUNCATEしてから全件INSERTする(冪等性確保)
```

### 3.2 オンライン処理(質問応答)

ユーザーがStreamlitのチャット画面から質問するたびに実行される処理。

```
① ユーザーがst.chat_inputに質問文を入力する
② app/rag_service.pyのanswer_question()が呼び出される
③ 質問文をGemini Embedding API(768次元)でベクトル化する
④ Cloud SQL(pgvector)にコサイン類似度検索を実行する
   ※ 上位3件を取得し、類似度0.5未満を除外する
⑤ 検索されたチャンク本文をコンテキストとしてプロンプトを構築する
⑥ Gemini API(gemini-2.5-flash-lite)に送信し自然文の回答を生成する
   ※ 「参考情報のみを根拠とすること」をプロンプトで明示する
⑦ Streamlit画面に回答と出典(ファイル名・条文番号)を表示する
```

## 4. システム構成要素一覧

| No | 構成要素 | 役割 | 採用技術・実装値 |
|---|---|---|---|
| 1 | データ取り込みバッチ | Markdown読込・分割・ベクトル化・DB格納 | Python / `python -m ingest.ingest` |
| 2 | Embedding API | テキストを768次元ベクトルに変換 | Gemini API / `models/gemini-embedding-001` / 768次元 |

| 5 | LLM(回答生成) | コンテキストをもとに自然文の回答を生成 | Gemini API / `gemini-2.5-flash-lite` |
| 6 | チャットUI | ユーザーとの対話画面 | Streamlit / `app/main.py` |
| 7 | ホスティング基盤 | Webアプリの実行環境 | Cloud Run / asia-northeast1 |
| 8 | ファイルストレージ | 就業規則Markdownの格納場所 | GCS / `fictworks-rule-data-501004` |
| 9 | 認証情報管理 | APIキーの管理 | 環境変数(ローカル: .env / Cloud Run: --set-env-vars) |

## 5. 採用方針の理由

| 検討項目 | 採用 | 理由 |
|---|---|---|
| ベクトルDB | Cloud SQL + pgvector | コストを低く抑えられ、停止・削除でコスト管理しやすい。768次元ならivfflatインデックスも使用可能(上限2000次元) |
| Embedding | Gemini API(gemini-embedding-001) | Vertex AI SDKがPython 3.12環境で全入力に同一ベクトルを返す不具合が発生したため切り替え。`output_dimensionality=768`を明示指定することで768次元に固定する |
| LLM | Gemini API(gemini-2.5-flash-lite) | `gemini-2.0-flash`は無料枠クォータ超過が発生。`genai.list_models()`で確認した有効モデルの中から選定 |
| フロントエンド | Streamlit | JavaScriptゼロ・Pythonのみで実装可能。チャットUIが標準搭載。コード量を大幅に削減できる |
| アプリ基盤 | Cloud Run | リクエストがない時間はスケール0で課金ゼロ。`--min-instances 0`設定が必須 |
| Pythonバージョン | 3.12 | 3.13以降はpydantic-core等でビルドエラーが発生するため使用しない |
| DBドライバ | pg8000 | psycopg2-binaryはPython 3.12環境でビルドエラーが発生するため使用しない |

## 6. データフローの概要

```
[GCS上のMarkdownファイル × 11]
      ↓ chunker.py / 正規表現で条文単位に分割
[チャンク × 82件]
      ↓ embedder.py / Gemini Embedding / 768次元 / retrieval_document
[チャンク本文 + メタデータ + 768次元ベクトル]
      ↓ ingest.py / TRUNCATE → INSERT
[Cloud SQL rule_chunksテーブル / 82レコード]
              ↑
              │ pgvector コサイン類似度検索(<=>演算子)
              │ 上位3件 / 類似度0.5以上のみ
[クエリベクトル(768次元)]
      ↑
      │ embedder.py / Gemini Embedding / 768次元 / retrieval_document
[ユーザーの質問文]
              ↓
[検索結果上位3件のチャンク + 質問文]
      ↓ llm_client.py / プロンプト構築 → Gemini API送信
[gemini-2.5-flash-liteによる自然文の回答]
      ↓ main.py / st.chat_message + st.expander
[Streamlit画面に回答 + 出典(ファイル名・条文番号)を表示]
```

## 8. コスト管理

| リソース | コスト管理方法 |
|---|---|
| Cloud SQL(rag-rules-db) | 不使用時は`--activation-policy=NEVER`で停止。完了後は削除 |
| Cloud Run | `--min-instances 0`でアクセスがない時間の課金をゼロにする |
| Gemini Embedding API | ingestは1回のみ実行。1回で82APIコールを消費(1日1000回の無料枠に対し約8%) |
| Gemini 生成 API | 1日20リクエストの無料枠を意識して確認用の質問回数を最小化する |
