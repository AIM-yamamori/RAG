## 1. システム概要

本システムは、就業規則(Markdownファイル)を知識源として、ユーザーの質問に対しLLMが根拠付きで回答するRAGチャットボットである。Google Cloud上に構築し、Webブラウザから**Streamlitのチャット画面**を通じて利用する。フロントエンドからバックエンドまで**Pythonのみ**で実装する。

処理は大きく「データ取り込み(オフライン処理)」と「質問応答(オンライン処理)」の2つに分かれる。

## 3. 処理フローの概要

### 3.1 オフライン処理(データ取り込み)

開発者がローカル環境から、就業規則のMarkdownファイルをCloud SQLに取り込む。この処理は初回構築時、およびデータ更新時のみ実行する。

1. Google Cloud Storage上のMarkdownファイルを読み込む
2. 条文(章・条)単位でチャンクに分割する
3. 各チャンクを**Gemini API(gemini-embedding-001、768次元)**でベクトル化する ※変更
4. チャンクの本文・メタデータ(ファイル名、章、条文番号)・ベクトルをCloud SQLに格納する

### 3.2 オンライン処理(質問応答)

ユーザーが**Streamlitのチャット画面**から質問すると、以下の流れで回答が生成される。※変更

1. ユーザーがStreamlitのチャット入力欄に質問を入力する
2. **Streamlitアプリ(Cloud Run上)**が質問を受け取りrag_service.pyを呼び出す ※変更
3. 質問文を**Gemini API(gemini-embedding-001)**でベクトル化する ※変更
4. Cloud SQL(pgvector)に対し、コサイン類似度の高いチャンクを検索する(上位3件)
5. 検索結果(チャンク本文)と質問文を組み合わせてプロンプトを構築する
6. Gemini API(gemini-2.5-flash-lite)にプロンプトを送信し、回答を生成する ※変更
7. 生成された回答と出典情報をStreamlit画面に表示する ※変更

## 5. 採用方針の理由

| 検討項目 | 採用 | 理由 |
|---|---|---|
| ベクトルDB | Cloud SQL + pgvector | Vertex AI Vector Searchは常時課金が発生し学習用途にはコストリスクが高い。Cloud SQLは最小構成で低コストに抑えられ、停止・削除も容易 |
| Embedding | **Gemini API(gemini-embedding-001)** ※変更 | Vertex AI SDKがPython 3.12環境で正常なベクトルを返さない不具合が発生。google-generativeaiライブラリ経由のGemini APIは安定動作を確認 |
| LLM | **Gemini API(gemini-2.5-flash-lite)** ※変更 | 無料枠があり安定動作を確認。gemini-2.0-flashはクォータ超過が発生したため切り替え |
| **フロントエンド** | **Streamlit(Python)** ※変更 | JavaScriptを一切使わずPythonのみで実装できる。チャットUIが標準機能として用意されており学習コストが低い。コード量が大幅に削減できる |
| アプリ提供形態 | Cloud Run | リクエストがない時間は自動的にインスタンス数0までスケールし、課金が発生しない。StreamlitアプリもDockerコンテナとしてデプロイ可能 |
| 開発言語 | **Python のみ** ※変更 | フロントエンド含め全てPythonで統一。JavaScriptの知識不要で学習目的に最適 |
