## 3. データベース設計

### 3.1 使用するデータベース

Cloud SQL for PostgreSQL 15(pgvector拡張を有効化)。インスタンスサイズはdb-f1-micro(学習用最小構成)とする。

- **インスタンス名**: rag-rules-db
- **プロジェクト**: my-project-rag-501004
- **リージョン**: asia-northeast1-b
- **接続名**: my-project-rag-501004:asia-northeast1:rag-rules-db

### 3.2 テーブル定義:`rule_chunks`

| カラム名 | 型 | NULL許可 | 説明 |
|---|---|---|---|
| id | SERIAL PRIMARY KEY | NOT NULL | チャンクの一意ID |
| source_file | VARCHAR(255) | NOT NULL | 元のMarkdownファイル名(例:`04_休暇制度.md`) |
| chapter_title | VARCHAR(255) | NULL可 | 章タイトル(例:`第4章 休暇制度`) |
| article_no | VARCHAR(50) | NULL可 | 条文番号(例:`第28条`) |
| article_title | VARCHAR(255) | NULL可 | 条文タイトル(例:`年次有給休暇`) |
| content | TEXT | NOT NULL | チャンクの本文テキスト |
| embedding | **VECTOR(768)** | NOT NULL | ベクトル埋め込み(**768次元** / gemini-embedding-001) |
| created_at | TIMESTAMP | NOT NULL | 登録日時(デフォルト:現在時刻) |

### 3.3 インデックス

| インデックス名 | 対象カラム | 種類 | 目的 |
|---|---|---|---|
| idx_rule_chunks_embedding | embedding | IVFFlat(pgvector) | 類似度検索の高速化(768次元はivfflat使用可) |
| idx_rule_chunks_source | source_file | B-tree | ファイル名での絞り込み |

### 3.4 テーブル作成SQL

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE rule_chunks (
    id SERIAL PRIMARY KEY,
    source_file VARCHAR(255) NOT NULL,
    chapter_title VARCHAR(255),
    article_no VARCHAR(50),
    article_title VARCHAR(255),
    content TEXT NOT NULL,
    embedding VECTOR(768) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT now()
);

CREATE INDEX idx_rule_chunks_embedding
    ON rule_chunks USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 10);
```

## 4. 画面設計(Streamlit チャットUI) ※全面変更

### 4.1 画面構成

Streamlitの標準チャットコンポーネントを使用する。FastAPIとHTMLによる実装を廃止し、Pythonのみで画面を構成する。

```
┌──────────────────────────────────────────┐
│  就業規則チャットボット                    │
│  株式会社フィクトワークス                     │
├──────────────────────────────────────────┤
│                                            │
│  [会話表示エリア(st.chat_message)]           │
│                                            │
│  ユーザー                                │
│  └ 年次有給休暇は何日もらえますか？           │
│                                            │
│  アシスタント                             │
│  └ 勤続6か月で10日付与されます…             │
│    ▼ 出典(expanderで折りたたみ)              │
│      04_休暇制度.md 第28条(年次有給休暇)     │
│                                            │
├──────────────────────────────────────────┤
│  [st.chat_input: 就業規則について質問...]    │
└──────────────────────────────────────────┘
```

### 4.2 Streamlit画面項目

| 項目 | Streamlitコンポーネント | 説明 |
|---|---|---|
| タイトル | `st.title` / `st.caption` | アプリ名・会社名を表示 |
| 会話表示エリア | `st.chat_message` | ユーザーとボットのメッセージを交互に表示 |
| 質問入力欄 | `st.chat_input` | 質問文を入力。Enter送信に対応 |
| ローディング表示 | `st.spinner` | 回答生成中に「回答を生成中...」を表示 |
| 出典表示 | `st.expander` | 「出典」として折りたたみ表示 |
| 会話履歴 | `st.session_state.messages` | セッション内の会話履歴をリストで管理 |

### 4.3 画面遷移

単一画面のみで構成し、画面遷移は発生しない。会話履歴は`st.session_state`に保持し、リロードで消去される。

### 4.4 main.pyの実装概要

```python
import streamlit as st
from app.rag_service import answer_question

st.title("就業規則チャットボット")
st.caption("株式会社フィクトワークス")

if "messages" not in st.session_state:
    st.session_state.messages = []

# 過去の会話を表示
for msg in st.session_state.messages:
    with st.chat_message(msg["role"]):
        st.write(msg["content"])

# 質問入力
if question := st.chat_input("就業規則について質問してください"):
    # ユーザーメッセージ表示
    st.session_state.messages.append({"role": "user", "content": question})
    with st.chat_message("user"):
        st.write(question)

    # 回答生成・表示
    with st.chat_message("assistant"):
        with st.spinner("回答を生成中..."):
            result = answer_question(question)
        st.write(result["answer"])
        if result["sources"]:
            with st.expander("出典"):
                for s in result["sources"]:
                    st.write(f"{s['source_file']} {s['article_no']}({s['article_title']})")

    st.session_state.messages.append(
        {"role": "assistant", "content": result["answer"]}
    )
```

## 6. 外部サービス連携仕様

### 6.1 Gemini Embedding API ※変更(Vertex AIから変更)

| 項目 | 内容 |
|---|---|
| 用途 | チャンク本文・質問文のベクトル化 |
| 使用モデル | **models/gemini-embedding-001** ※変更 |
| 出力次元数 | **768次元**(output_dimensionality=768 を明示指定) |
| 呼び出しタイミング | (1)データ取り込みバッチ実行時(チャンクごと) (2)質問応答時(質問文ごと) |
| 認証方式 | **APIキー(GEMINI_API_KEY環境変数)** ※変更 |
| レート制限(無料枠) | 100リクエスト/分、1,000リクエスト/日 |
| task_type | 取り込み時: `retrieval_document` / 検索時: `retrieval_document` |

### 6.2 Gemini LLM API ※変更

| 項目 | 内容 |
|---|---|
| 用途 | 検索されたコンテキストをもとにした回答生成 |
| 使用モデル | **gemini-2.5-flash-lite** ※変更(gemini-2.0-flashからクォータ超過のため変更) |
| 呼び出しタイミング | 質問応答時(検索完了後) |
| 認証方式 | APIキー(GEMINI_API_KEY環境変数) |
| レート制限(無料枠) | 10リクエスト/分、20リクエスト/日 |
| プロンプト構成 | システム指示+検索されたチャンク本文(コンテキスト)+ユーザーの質問 |

### 6.3 Secret Manager / 環境変数

| 変数名 | 内容 |
|---|---|
| GEMINI_API_KEY | Gemini APIのAPIキー |
| GOOGLE_CLOUD_PROJECT | GCPプロジェクトID(my-project-rag-501004) |

## 7. コスト管理設計

| 項目 | 内容 |
|---|---|
| 予算アラート | Cloud Billingで予算を設定し、50%・90%・100%到達時にメール通知する |
| Cloud SQL運用 | 検証作業を行わない時間帯はインスタンスを停止する(`--activation-policy=NEVER`) |
| Cloud Run運用 | 最小インスタンス数を0に設定し、アクセスがない時間は課金を発生させない |
| Embedding API管理 | データ取り込みは1回のみ実行。再実行を避ける(1日1,000回制限に注意) |
| LLM API管理 | 動作確認の質問回数を最小限にする(1日20回制限に注意) |
